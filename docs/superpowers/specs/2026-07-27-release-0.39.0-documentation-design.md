# AgentsView 0.39.0 Documentation Refresh Design

## Goal

Publish a comprehensive, implementation-accurate documentation refresh for the
AgentsView 0.39.0 release. The refresh should make the mature user-facing
changes easy to discover, correct stale feature documentation, acknowledge
contributors in the established release style, and avoid overstating
experimental work.

## Release Narrative

The 0.39.0 release documentation will lead with mature user-facing changes:

- Poolside Agent CLI, RooCode, Kilo's legacy VS Code extension, and Trae session
  support;
- French localization;
- guided semantic-search setup in the command palette;
- daily machine usage, subagent cost rollups, repository context, and session
  age;
- the DuckDB mirror's simplified local-push contract and safely rebuildable
  derived-data model;
- bounded background work and semantic-search reliability improvements; and
- the user-visible correctness fixes summarized in the release changelog.

Recall will remain clearly labeled experimental. Its documentation will be
corrected to cover scheduled extraction, vector and hybrid retrieval, and the
read-only session evidence panel, but these capabilities will not be promoted on
the homepage or treated as mature workflows.

The artifact work will receive only a brief, carefully scoped changelog mention.
It is an experimental internal foundation: version 1 wire types and a local
DocBank-backed content store exist, but export/import pipelines, transports,
server integration, and CLI workflows do not.

## Documentation Changes

### Changelog and acknowledgements

Add a dated 0.39.0 section to `docs/changelog.md`, organized into new features,
improvements, bug fixes, and acknowledgements. The supplied release summary is
the editorial baseline, while the merged implementation and tests are the source
of truth for precise wording and limitations.

Move the two existing Unreleased DuckDB improvements into 0.39.0 because their
implementing commit is included in the release tag. Retain an empty Unreleased
heading for future changes. Treat the removal of remote `duckdb push` as a
user-visible compatibility change: local mirror pushes remain supported, while
configured remote Quack endpoints remain read-only inputs for `duckdb status`
and `duckdb serve`.

Use the established “Thanks to…” acknowledgement style with GitHub profile
links. Credit the human authors represented in the release's product and
documentation changes—`wesm`, `mjacobs`, `tylergibbs1`, `ajinkyajacob`,
`scross01`, `berenddeboer`, `gtkacz`, `mariusvniekerk`, `rodboev`, `delattre1`,
`chikei`, `xkrogen`, `riordan`, `serverless83`, `dpanbug`, `cpcloud`,
`ShiroKSH`, `Technophobe01`, `bangddong`, and `jahabdank`—plus `maphew`, whose
artifact-foundation contribution is called out in the merged pull request.
Exclude dependency bots and group related contributions so the section remains
readable.

### Provider discovery

Keep provider discovery synchronized across:

- `README.md`;
- the homepage agent grid and multi-agent summary in `docs/index.md`;
- the custom-directory examples in `docs/quickstart.md`;
- the authoritative discovery table and environment examples in
  `docs/configuration.md`; and
- the environment-variable reference in `docs/commands.md`.

Poolside, RooCode, Kilo (legacy), and Trae must use the names, environment
variables, config keys, default directories, and limitations implemented in
`internal/parser/types.go` and their parser packages. Trae documentation must
state that legacy inline chats are supported while detected encrypted modern
layouts are reported as unsupported.

### Mature feature guides

Update `docs/usage.md` and related focused pages where necessary to document:

- French as a selectable interface language;
- guided semantic-search setup states, browser-triggered embedding builds,
  progress polling, and automatic search retry;
- descendant subagent cost rollups in session totals;
- repository context in trace analysis;
- collapsed call details and clearer inline teammate labeling; and
- CLI search result age where the CLI reference discusses session search.

Do not repeat implementation details that belong in existing focused pages. Link
to the Semantic Search, Token Usage, Session API, and configuration guides where
that produces a clearer user path.

### Experimental feature corrections

Revise `docs/recall.md` to remove the obsolete statements that Recall is
lexical-only and has no web UI. Document:

- lexical, vector, and hybrid query modes, with lexical remaining the default;
- the separate `recall` embedding store and the explicit
  `[vector.embed] recall = true` automatic-embedding consent;
- stale-corpus fail-closed behavior and the
  `agentsview embeddings build --store recall` remediation;
- the read-only per-session evidence panel and evidence navigation; and
- the existing local/SQLite, trust, review-state, and experimental limitations.

Retire or rewrite speculative “future direction” statements that now contradict
shipped extraction and retrieval behavior. Keep the warning and overall tone
conservative.

Do not add a public artifact guide in this release. The changelog description
must explicitly identify the artifact work as a foundation without a current
user workflow.

## Screenshots

Add one reproducible screenshot for the guided semantic-search setup panel. The
existing screenshot harness should drive the real 0.39.0 frontend into the
unconfigured semantic-search state and capture the setup instructions without
private data.

The new screenshot name must be registered together in:

- `docs/screenshots/tests/screenshots.spec.ts`;
- `docs/assets/hydrate-assets.sh`;
- `docs/screenshots/update-generated-assets-branch.sh`; and
- `scripts/docs_assets_test.go`.

The implementation order is fixed: update the harness and manifests, regenerate
the PNG through the Docker screenshot harness, update and force-push the
`docs-generated-assets` orphan branch, hydrate that published asset, and only
then run the documentation build/check that references it. The feature branch
must not be published while its docs source points at an asset absent from the
orphan branch.

Do not add a promotional Recall screenshot. Existing screenshots should only be
regenerated when the documented UI has materially changed or visual inspection
shows that the current asset no longer matches the text.

Generated PNGs remain on the `docs-generated-assets` orphan branch; only
screenshot harness changes belong on the feature branch.

## Verification

Before the final commit:

1. Compare every 0.39.0 changelog statement with the implementing commits,
   source, tests, or CLI help.
1. Verify contributor names and GitHub handles from the merged pull requests.
1. Run Markdown formatting with the repository's configured formatter.
1. Run the documentation build and checks using locally hydrated asset branches.
1. Run the targeted screenshot test and visually inspect the new image.
1. Search public docs for stale contradictions, missing provider variables,
   outdated language lists, broken local links, private terms, and absolute
   paths.
1. Keep generated site output and image media out of the feature-branch commit.

## Non-Goals

- Reorganizing the documentation information architecture.
- Promoting Recall as a stable end-user feature.
- Documenting an artifact export/import or synchronization workflow that does
  not yet exist.
- Rewriting adjacent guides that remain accurate.
- Changing product behavior as part of the documentation refresh.
